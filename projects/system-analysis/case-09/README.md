# 🚲 Кейс №09 — Мобильное приложение «Прокачу»

## 1. Протокол встречи со стейкхолдерами
* **Дата:** 12.03.2026
* **Время:** 10:00 – 11:30
* **Место:** Переговорная офиса "Прокачу"
* **Участники:** Иванов А. (руководитель), Петрова А. (оператор), Соколов Д. (тех. директор), [Ваше имя] (аналитик)
* **Цель встречи:** Сбор требований к мобильному приложению

### Ключевые тезисы встречи:
1. Текущая аренда через бота — 8 шагов, неудобно. Нужно приложение.
2. Интеграция с замками должна осуществляться по Bluetooth (BLE) на случай перебоев с GSM.
3. Поддержка должна мгновенно видеть статус завершения аренды и фиксацию закрытия замка.
4. Авторизация пользователей должна быть максимально простой — по номеру телефона и СМС.
5. Приложение должно поддерживать интерактивную карту для быстрого поиска свободных байков.
6. Ввод платежных карт должен быть безопасным и соответствовать регламентам безопасности.

## 2. Систематизация данных
* **Предметная область:** Сервис аренды велосипедов "Прокачу". 200 велосипедов, 20 станций. Аренда через бота.

### Бизнес-процессы:
1. Регистрация (телефон, email) и привязка карты.
2. Поиск и бронирование велосипеда на карте.
3. Сканирование QR-кода и разблокировка замка (Старт аренды).
4. Перевод аренды в режим ожидания (Пауза).
5. Завершение аренды на станции и автоматическое списание средств.

### Роли:
1. Клиент — ищет, бронирует, арендует.
2. Оператор поддержки — обрабатывает тикеты, корректирует баланс при сбоях.
3. Техник — обслуживает велосипеды, меняет батареи смарт-замков.

### Проблемы:
1. Бот неудобный — 8 шагов.
2. Долгое ожидание ответа от замка при слабом сигнале сети.
3. Клиенты оставляют велосипеды вне разрешенных зон парковки.
4. Отсутствие напоминаний об активной аренде в режиме паузы.
5. Высокая нагрузка на поддержку из-за ручного закрытия проблемных сессий.

### Явные пожелания:
1. Нативное приложение на iOS и Android.
2. Старт поездки по сканированию QR-кода.

### Скрытые пожелания (Допущение):
1. Push-уведомления (Допущение).
2. Кэширование геоданных для отображения карты без интернета.

## 4. Требования к системе

### Функциональные требования (ФТ):
* **ФТ-01. Отображение карты**
  * *Система должна:* показывать карту со станциями и свободными велосипедами.
  * *Пояснение:* Клиент видит ближайшие станции сразу.
* **ФТ-02. Авторизация по СМС**
  * *Система должна:* отправлять 4-значный код на введенный телефон для входа.
  * *Пояснение:* Быстрый вход без пароля.
* **ФТ-03. Распознавание QR-кода**
  * *Система должна:* открывать камеру для сканирования кода на замке велосипеда.
  * *Пояснение:* Исключает ручной ввод номера велосипеда.
* **ФТ-04. Бронирование**
  * *Система должна:* закреплять велосипед за клиентом на 10 минут до поездки.
  * *Пояснение:* Гарантия, что байк не заберет кто-то другой.
* **ФТ-05. Расчет стоимости**
  * *Система должна:* рассчитывать цену на основе тарифа и минут поездки.
  * *Пояснение:* Прозрачность списаний для пользователя.
* **ФТ-06. Контроль геозоны**
  * *Система должна:* проверять нахождение байка на станции при закрытии аренды.
  * *Пояснение:* Защита от брошенных в неположенных местах велосипедов.
* **ФТ-07. Привязка карты**
  * *Система должна:* верифицировать карту через холдирование 1 рубля.
  * *Пояснение:* Проверка платежеспособности до старта.
* **ФТ-08. Режим «Пауза»**
  * *Система должна:* временно блокировать замок без завершения общего проката.
  * *Пояснение:* Позволяет отойти в магазин, сохранив байк за собой.
* **ФТ-09. Окно поломок**
  * *Система должна:* отправлять отчет о неисправности с описанием и фото.
  * *Пояснение:* Оперативное информирование техников.
* **ФТ-10. Отправка чеков**
  * *Система должна:* генерировать и высылать фискальный чек после оплаты.
  * *Пояснение:* Соблюдение законодательства (54-ФЗ).

### Нефункциональные требования (НФТ):
* **НФТ-01. Загрузка карты**
  * *Характеристика:* Производительность.
  * *Значение:* Не дольше 3 секунд.
  * *Пояснение:* При Wi-Fi/4G.
* **НФТ-02. Время открытия замка**
  * *Характеристика:* Скорость отклика.
  * *Значение:* До 5 секунд с момента нажатия кнопки «Старт».
  * *Пояснение:* Исключает долгое ожидание у велосипеда.
* **НФТ-03. Безопасность транзакций**
  * *Характеристика:* Защищенность.
  * *Значение:* Использование токенизации Rebill ID (PCI DSS compliant).
  * *Пояснение:* Данные карт не сохраняются в системе.
* **НФТ-04. Обновление координат**
  * *Характеристика:* Сетевая нагрузка.
  * *Значение:* Отправка геопозиции раз в 30 секунд.
  * *Пояснение:* Для точного трекинга маршрута.
* **НФТ-05. Локальный кэш**
  * *Характеристика:* Надежность.
  * *Значение:* Объем оффлайн-данных в памяти устройства до 50 МБ.
  * *Пояснение:* Сохранение карты разрешенных зон при обрыве сети.
* **НФТ-06. Доступность API**
  * *Характеристика:* Нагрузочная способность.
  * *Значение:* Обработка до 2000 запросов в секунду (RPS).
  * *Пояснение:* Стабильность работы в часы пик.
