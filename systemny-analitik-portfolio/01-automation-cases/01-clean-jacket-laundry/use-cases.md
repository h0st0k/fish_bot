# Кейс: Модернизация процессов химчистки «Чистый пиджак»

## 1. Ролевая модель и пользовательские истории
*   **Клиент (Арендатор):** «Как Клиент, я хочу видеть актуальный статус готовности моих вещей в приложении, чтобы не тратить время на звонки операторам и точно знать, когда забирать заказ» [01-104].
*   **Оператор (Приемщик):** «Как Оператор, я хочу создавать новые заказы в электронном виде через систему, чтобы избежать путаницы с бумажными квитанциями и не терять данные клиентов» [01-104].
*   **Курьер:** «Как Курьер, я хочу получать список адресов и выбранных дат для доставки вещей, чтобы вовремя забирать и привозить заказы клиентам на дом» [01-104].

## 2. Сценарий прецедента «Оформить заказ на химчистку с доставкой»
*   **Предусловие:** Пользователь успешно авторизован, вещи подготовлены к сдаче [01-104].
*   **Постусловие:** Заказ создан в статусе «Принят», сформирована задача курьеру [01-104].

### Основной поток (Happy Path — Атомарные шаги) [01-104]:
1. Клиент выбирает в каталоге услугу «Химчистка» и указывает тип вещи [01-104].
2. Клиент выбирает способ получения «Вызов курьера» [01-104].
3. Клиент указывает адрес и желаемую дату сдачи вещей [01-104].
4. Клиент выбирает способ оплаты «Карта онлайн» [01-104].
5. Клиент нажимает кнопку «Оплатить заказ» [01-104].
6. Система отображает экран успешного создания заказа со статусом «Принят» [01-104].

### Альтернативный поток (Шаг 4а) [01-104]:
1. Клиент выбирает способ оплаты «Наличные при получении» [01-104].
2. Клиент нажимает кнопку «Оформить заказ» [01-104].
3. *Возврат:* Сценарий продолжается с шага 6 основного потока [01-104].

### Исключительный поток (Шаг 5.1) [01-104]:
1. Система отправляет запрос в банк и получает отказ в авторизации карты [01-104].
2. Система выводит сообщение: «Ошибка оплаты. Проверьте баланс или выберите другой способ» [01-104].
3. *Результат:* Цель не достигнута, система возвращает пользователя на шаг 4 [01-104].
