# 🐾 Остров 2. Кейс: Онлайн-запись в ветклинику «Лапка»

## 🧭 Бортовой журнал экспедиции
> **Контекст миссии**: Владелец клиники «Лапка» столкнулся с тем, что администраторы вручную ведут графики приёма в Excel, из-за чего возникают накладки («овербукинг»). Нам поручено спроектировать логику автоматического выбора 30-минутных слотов, составить первую структуру сущностей (Data Model) и проработать сценарии обработки ошибок.

---

## 📐 1. Модель данных (Data Model)

Для обеспечения целостности данных были спроектированы 4 ключевые сущности реляционной базы данных:

1.  **Клиент** (`ID`, `ФИО`, `Телефон`, `Email`).
2.  **Врач** (`ID`, `ФИО`, `Специализация`, `Тип графика`).
3.  **Расписание** (`ID`, `ID_Врача`, `Дата`, `Время_Начала`, `Время_Окончания`, `Статус_Доступности`).
4.  **Запись** (`ID`, `ID_Клиента`, `ID_Врача`, `Дата`, `Время`, `Статус_Записи`).

---

## ⚙️ 2. Сценарий «Клиент записывается на приём» (Use Case)

**Happy Path (Основной успешный поток):**
1. Клиент выбирает специализацию врача (например, *Хирург*).
2. Система запрашивает бэкенд и отображает список доступных врачей данной специализации.
3. Клиент выбирает конкретного врача и желаемую дату.
4. Система проверяет таблицу `Расписание` и выводит свободные 30-минутные слоты.
5. Клиент выбирает время, вводит свой номер телефона и нажимает кнопку «Записаться».
6. Система создает запись в таблице `Запись` со статусом `Подтверждена`, меняет статус слота на `Занято` и выводит экран успеха.

---

## 🚨 3. Инженерия исключений: Борьба с конкурентной записью

Критическая точка отказа системы — когда два клиента одновременно открыли один и тот же слот приёма и нажали кнопку «Записаться» в одну и ту же секунду.

*   **Исключительный сценарий (Сбой, ошибка `409 Conflict`):**
    *   *Действие*: Клиент №1 и Клиент №2 отправляют запросы `POST /appointments`.
    *   *Реакция бэкенда*: Запрос Клиента №1 обрабатывается на доли секунды быстрее. Система блокирует строку в БД и создает запись.
    *   *Реакция для Клиента №2*: Система обнаруживает, что статус слота уже изменился на `Занято`. Бэкенд отклоняет транзакцию и возвращает HTTP-код ответа **`409 Conflict`**.
    *   *Интерфейс*: Приложение Клиента №2 не падает, а выводит понятное сообщение: *«Упс! Это время только что забронировали. Пожалуйста, выберите другой свободный слот»* и автоматически обновляет сетку расписания.

---

## 🏁 Результат миссии
Проектирование логики расписания исключает человеческий фактор и накладки. База данных готова к развертыванию, а фронтенд-разработчики получили четкие правила обработки кодов ошибок бэкенда.
