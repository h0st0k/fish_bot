# 🏢 Остров 3. Кейс: Система бронирования рабочих мест в коворкинге

## 🧭 Бортовой журнал экспедиции
> **Контекст миссии**: Крупная сеть коворкингов задыхается от ручного управления: сотрудники бронируют столы и переговорные через чаты, что приводит к хаосу и конфликтам. Нам поручено разложить проект по методологии «Задача ➔ Артефакт ➔ Результат» и спроектировать структуру контрактов API для интеграции веб-интерфейса с бэкендом.

---

## 📐 1. Триада аналитика: Сквозная цепочка проектирования

Работа над проектом была структурирована по фазам жизненного цикла системы:

*   **Выявление требований**:
    *   *Задача СА*: Проведение интервью, выделение ролей (Сотрудник, Администратор), фиксация бизнес-правил и ограничений (только веб-версия).
    *   *Артефакт*: Документ **Vision & Scope** и структурированный бэклог.
    *   *Результат*: Чёткие границы проекта на старте, исключающие разрастание скоупа.
*   **Проектирование**:
    *   *Задача СА*: Проектирование реляционной структуры данных и веб-сервисов.
    *   *Артефакты*: **ER-диаграмма данных** (Сотрудник, Место, Бронь) и **Контракты API**.
    *   *Результат*: Готовый технический фундамент для параллельной работы бэкенд- и фронтенд-разработчиков.
*   **Разработка и Сопровождение**:
    *   *Задача СА*: Управление изменениями (Change Management), проработка альтернативных сценариев удаления.
    *   *Артефакт*: Запрос на изменение (RFC) и аналитическая записка по логированию статусов.
    *   *Результат*: Мягкое удаление броней (логическое удаление через статус `отменена`) для сохранения исторической аналитики.

## ⚙️ 2. Проектирование REST API Контрактов (Swagger/OpenAPI)

Для реализации бэкенд-сервисов аналитиком были формализованы спецификации эндпоинтов:

### Метод создания бронирования места
*   **HTTP-метод**: `POST`
*   **Путь (Endpoint)**: `/api/v1/bookings`
*   **Тело запроса (Request Body - JSON)**:
    ```json
    {
      "employee_id": 451,
      "workspace_id": 12,
      "booking_date": "2026-07-20",
      "slot_type": "full_day"
    }
    ```
*   **Успешный ответ (Response 201 Created)**:
    ```json
    {
      "booking_id": 8902,
      "status": "confirmed",
      "created_at": "2026-07-16T10:15:30Z"
    }
    ```
*   **Коды ошибок**:
    *   `400 Bad Request` — неверный формат даты или указан прошедший день.
    *   `409 Conflict` — данное рабочее место на выбранную дату уже занято другим сотрудником.
