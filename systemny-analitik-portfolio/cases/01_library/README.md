# 🏛️ Остров 1. Кейс: Приложение для Районной Библиотеки

## 🧭 Бортовой журнал экспедиции
> **Контекст миссии**: Жители района хотят современное мобильное приложение для взаимодействия с локальной библиотекой, чтобы не носить с собой бумажные читательские билеты и удаленно бронировать книги. Это наш первый сквозной кейс для отработки фундаментальных навыков выявления границ системы и декомпозиции требований.

---

## 📐 1. Границы системы (Scope & Boundaries)

Системный аналитик очертил жесткие рамки MVP-версии продукта, чтобы избежать разрастания скоупа (Scope Creep):

*   **Внутри границ (In Scope)**:
    *   Выпуск виртуального читательского билета с QR-кодом.
    *   Поиск книг по каталогу (название, автор, жанр).
    *   Удаленное бронирование доступной книги на 48 часов.
    *   Push-уведомления о приближении срока возврата литературы.
*   **Вне границ (Out of Scope)**:
    *   Онлайн-чтение электронных или прослушивание аудиокниг.
    *   Платная подписка или интеграция платежных шлюзов (все услуги бесплатны).
    *   Модуль закупки новых книг для администрации библиотеки.

---

## 🗂️ 2. Декомпозиция функций (Иерархия требований)

Для разработчиков функции системы были детализированы до атомарного уровня:

1.  **Модуль «Каталог»**
    *   `REQ-LIB-01`: Система должна обеспечивать полнотекстовый поиск по базе данных книг.
    *   `REQ-LIB-02`: Система должна отображать текущий статус экземпляра (*«В наличии» / «На руках до ХХ.ХХ»*).
2.  **Модуль «Бронирование»**
    *   `REQ-LIB-03`: Система должна блокировать книгу для других пользователей ровно на 48 часов в момент нажатия кнопки «Забронировать».
    *   `REQ-LIB-04`: Система должна автоматически отменять бронь и возвращать книгу в каталог, если читатель не забрал её в течение 48 часов.
3.  **Модуль «Профиль читателя»**
    *   `REQ-LIB-05`: Система должна генерировать уникальный QR-код читательского билета для сканирования на стойке выдачи.
