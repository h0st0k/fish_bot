# Кейс 04 — Бонусный раунд (5 плохих требований)

📍 **[#кейс-бонус-диаграммы](#кейс-бонус-диаграммы)**

---

## 📝 Пять плохих требований

| № | Требование |
|---|------------|
| 1 | «Система должна работать за установленное время (не более X секунд) и стабильно» |
| 2 | «Интерфейс должен быть эргономичным и понятным для пользователя» |
| 3 | «Система должна обеспечивать заданный уровень безопасности» |
| 4 | «Уведомления должны доставляться вовремя и содержать всю необходимую информацию» |
| 5 | «Пользователь должен быть доволен скоростью работы системы» |

---

## 🎯 Задание
Назови, какой критерий нарушен в каждом требовании. Время — 3 минуты.

---

## 🔍 Разбор

| № | Нарушенные критерии | Исправление |
|---|----------------------|-------------|
| 1 | **Testable + Однозначность** | «Время отклика ≤ 0.5 секунды, доступность 99.9%» |
| 2 | **Однозначность + Testable** | Описать конкретные UI-элементы |
| 3 | **Testable + Однозначность + Трассировка** | Перечислить механизмы, указать источник |
| 4 | **Testable + Однозначность + Полнота** | Указать время, поля, каналы |
| 5 | **Valuable (золотое покрытие)** | Удалить или заменить на NPS |

---

## 🧠 Главный вывод
> **Любое субъективное прилагательное должно быть заменено на измеримый критерий. Если замена невозможна — требование удаляется.**
