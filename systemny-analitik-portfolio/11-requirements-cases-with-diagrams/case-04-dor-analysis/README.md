# 🎯 Артефакт: Анализ DoR (Definition of Ready)

Чек-лист проверки требования «Оформление заказа» перед передачей спринт-команде.

| Критерий готовности | Статус | Комментарий аналитика |
| :--- | :---: | :--- |
| **Описана ценность?** | 🍏 ДА | Сформулирована в User Story («Получить доставку»). |
| **Есть Acceptance Criteria?** | 🍏 ДА | 8 конкретных критериев покрывают основные и граничные кейсы. |
| **Атомарность требования?** | 🍏 ДА | Логически завершённый блок, реализуемый за один спринт. |
| **Команда может оценить?** | 🍏 ДА | Критерии достаточно конкретны для планирования задач. |
| **Нет блокирующих зависимостей?** | 🍎 БЛОКЕР | Требуется выбор платёжного шлюза для онлайн-оплаты картой. |
| **Макеты интерфейса готовы?** | 🍎 НЕТ | Макеты экрана оформления отсутствуют. |

### ⚠️ Итоговый вердикт аналитика
Требование **НЕ ГОТОВО** к передаче в разработку. Необходима доработка по трем выигрышным пробелам:
1. Предоставить макеты UI экрана оформления заказа.
2. Утвердить интеграционное решение по платёжному шлюзу.
3. Зафиксировать нефункциональные требования по скорости обработки запросов.
